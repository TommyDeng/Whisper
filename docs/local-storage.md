# 本地存储与保留策略

实现在 `lib/storage/` 和 `lib/messaging/messaging_service.dart`。

## 数据库加密

- 一个 SQLite 文件（`whisper.db`，联调时 `whisper-<profile>.db`），用 SQLite3 Multiple Ciphers 整库加密
  （`pubspec.yaml` 的 `hooks.user_defines.sqlite3.source: sqlite3mc`）。
- 密钥是 32 字节随机数，存在系统安全存储里（`db_key` / `db_key.<profile>`），和身份私钥放在一起。
- 旧版本留下的未加密库在第一次打开时就地加密，数据保留。
- 库是加密的但密钥找不到了（密钥环被清空、换了系统账号）：内容已无法读出。旧文件改名为
  `whisper.db.unreadable-<时间>` 留在原处，应用另建一个空库继续运行。
- 消息正文在库里仍然是端到端加密的密文，整库加密额外保护联系人、时间等元数据。

## 保留

| 规则 | 行为 |
| --- | --- |
| 7 天自动删除 | 启动时和之后每小时一次，删除时间早于 7 天的全部消息（包括没读的和阅后即焚的）以及同样旧的待发回执。 |
| 阅后即焚 | 按会话开关，只影响自己之后发出的消息。接收方显示消息时发 `read` 回执，离开聊天页（或下次启动）时删除；发送方收到回执后删除。依赖对方客户端配合，防不了截屏。 |
| 删除联系人 | 删除这个会话的消息和待发回执。 |
| 清除全部数据 | 联系人页右上角菜单。断开所有连接，删除数据库文件和它的密钥，删除身份私钥；之后生成新身份，回到首次启动的状态。对方设备上的数据不受影响。 |

## 重新配对

与同一台设备重新配对会得到新的会话 ID（角色也可能互换）。密文绑定了会话 ID 和角色，所以旧消息要用旧会话密钥
解开、用新会话重新加密后搬到新会话下，消息 ID、时间和焚毁标记不变。

- 解不开的旧消息（例如自己的身份重置过）直接删除。
- 对方还没确认送达的消息由新会话重发；消息 ID 不变，对方已有的会去重。
- 旧会话还没发出去的回执丢弃。
- 阅后即焚开关沿用旧联系人的设置。
